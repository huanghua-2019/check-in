# word 归位 填写规范

## 问题是什么

`word` 字段本该是**那条可以被直接抄进去的话**，现在却是它的**说明书**。

| id | 现在的 word（错） | example（原话） | 应该改成 |
|---|---|---|---|
| 883 | 不同行业或企业的固有风险存在差异。 | 正如销售天然气的企业会比销售沙子的企业发生更多的爆炸一样。 | **卖天然气的企业比卖沙子的更容易爆炸** |
| 1381 | 仅仅因为问题尚未发生，不代表问题不存在。 | 芒格：……如果你从42楼的窗户跳出去，在你经过20楼的时候，还是很不错的。 | **从42楼跳出去，经过20楼时还挺不错** |
| 1216 | 分析个人/企业潜力时，强调本质资质是成长的核心前提 | 丑小鸭能变成天鹅，那是因为它本身就是天鹅。 | **丑小鸭能变天鹅，因为它本来就是天鹅** |

列表页显示的是 `word`。用户要"写的时候调得出"，就必须一眼看到那句能用的原话，而不是它的解释。

## 改写规则

1. **word = example 里那句最锋利的话**，压到 ≤22 字（可含逗号）。保留原话的具体意象、数字、比喻物。
2. **禁止**任何"形容……/强调……/讽刺……/说明……/描述……"式说明书前缀。
3. example 是长段落时，**挑出段落里最有冲击力的那个短语**，不要自己概括成抽象概念。
4. **不要改成书面雅词**——原话是口语就保持口语（"挺不错"不要改成"尚可"）。
5. **严禁编造**：改出来的字必须能在 example 里找到来源。
6. 若原 example 确实只有一句陈述、没有形象化表达（少见），就把 example 那句话压短作 word，别硬造比喻。

## use 复核（每一条都要给）

从下面 17 类里选 **1~2 个**（数组）：

`🎯 立论判断` `🔗 论证推理` `⚖️ 对比转折` `📊 举证说明` `💡 打比方` `🔍 洞察本质` `⚠️ 警示风险` `🏆 竞争格局` `👥 人性心理` `🏗️ 管理组织` `💰 投资决策` `🌿 人生修养` `🧩 用词精准` `📐 概念指代` `🖋️ 描写刻画` `✍️ 写作技法` `😂 幽默调侃`

- 首元素是**主用途**（决定它在列表里归到哪一组）。
- **`💡 打比方` 的用法**：当这条的价值就是"把一个复杂道理用一个类比说清"时，加在**第二位**。不要给所有比喻都加，只给"作者本意就是化繁为简"的那些。
- 可以修正现给出的 use（现给的是按旧分类机械映射的，不一定准）。

## mean 返工（只在需要时）

`mean` 现在有两种毛病：**与 word/syn 完全一样**、或**只是把 word 换个说法复述**。
遇到这两种，重写成"**把这句话背后的道理直白讲清楚**"（≤60 字）。
两个字段同时出现时（本片只有 cases 的 9 条标了 `needmean`），**必须**重写 mean。
其余 mean 若本身已说清道理，**不要动**。

## 输出格式

写文件 `build/wordpatch/<分片>.json`，UTF-8，`ensure_ascii=False`：

```json
{
  "883": {"word": "卖天然气的企业比卖沙子的更容易爆炸", "use": ["⚠️ 警示风险", "💡 打比方"]},
  "1381": {"word": "从42楼跳出去，经过20楼时还挺不错", "use": ["🔍 洞察本质", "💡 打比方"], "mean": "重写后的释义（仅需要时给）"}
}
```

- key 是条目 id 的**字符串**。
- 每一条都**必须**有 `word` 和 `use`。
- `mean` **只在需要返工时**才出现。
- 不要输出示例里的 id，那是真实数据，会被覆盖。

