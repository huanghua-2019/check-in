# 词库维度说明（2026-10-09 重建）

## 一条条目长什么样

```js
{
  "id": 1381,                        // 主键，打卡进度靠它，只增不改
  "tab": "met",                      // 形式：词汇/句式/比喻/金句/辨析/幽默/案例/规则
  "tier": "进阶",                    // 分级：核心 / 进阶 / 备用
  "use": ["🔍 洞察本质", "💡 打比方"], // 用途，1~2 个，第一个是主用途（决定列表归到哪组）
  "cat": "🧠 认知与思维",             // 旧分类，仅留档，前端不再使用
  "word": "从42楼跳出去，经过20楼时还挺不错",  // 列表上显示的那一句，能直接抄走
  "syn": "没爆雷不代表没有雷、侥幸无实仍是风险",
  "mean": "有些问题眼下还没爆发，但隐患早已注定。",
  "example": "芒格：……如果你从42楼的窗户跳出去……",
  "scene": "警示侥幸心理时用。"
}
```

## 17 类用途（跨 7 个形式统一）

决定"你要写什么动作"时该翻哪一格。脚本 `apply_use.py` 里 `CAT2USE` 是唯一映射表。

| 用途 | 什么时候用 | 主要来自 |
|---|---|---|
| 🎯 立论判断 | 下结论、表态、断言 | 01-观点与论述、判断断言类 |
| 🔗 论证推理 | 因果、条件、递进、逻辑连接 | 02-逻辑关系、因果分析类、逻辑与论证 |
| ⚖️ 对比转折 | 对照、让步、反衬 | 对比揭示类 |
| 📊 举证说明 | 举例、数据、引用、列举 | 案例库、列举论证类、数据论证类 |
| 💡 打比方 | 用类比把复杂说简单 | 由 agent 逐条判定，附在第二位 |
| 🔍 洞察本质 | 揭示规律、看穿表象 | 认知与思维、规律与真相、变化与趋势 |
| ⚠️ 警示风险 | 隐患、教训、反面 | 风险与警示 |
| 🏆 竞争格局 | 优势、壁垒、品牌、胜负 | 竞争与生存、商业判断、品牌与消费 |
| 👥 人性心理 | 动机、认知偏差、人际 | 人性与认知、人性与关系 |
| 🏗️ 管理组织 | 领导、制度、用人 | 组织与管理、管理与领导力 |
| 💰 投资决策 | 估值、仓位、心态、宏观 | 投资理念、估值与财务、宏观与周期、投资心态 |
| 🌿 人生修养 | 心态、习惯、成长 | 人生感悟 |
| 🧩 用词精准 | 动词、形容词、程度词 | 03-程度与属性、04-行为与动作 |
| 📐 概念指代 | 名词、术语 | 05-事物与指代、06-概念与术语 |
| 🖋️ 描写刻画 | 写人、写物、写环境 | 07A/B/C/D-素材与描写 |
| ✍️ 写作技法 | 句式、开篇、收束、修辞 | 各种句式模板类 |
| 😂 幽默调侃 | 自嘲、讽刺、玩梗 | 五种幽默分类 |

> 为什么是 17 类而不是最初提的 15 类：词汇侧（约 40% 条目）原本挤在「描写刻画」一格，落到 356 条，没法用。拆成「用词精准 / 概念指代 / 描写刻画」三格后才可用。

## 分级 tier（可解释的规则，非人工主观打分）

| 档 | 规则 | 参考条数 |
|---|---|---|
| 核心 | 句式 + 写作规则 + 词汇里的 01/02/03 三类功能词（写作骨架，复用率最高） | ~435 |
| 进阶 | 词汇 04/05/06 三类；以及用途落在投资/竞争/风险/洞察/对比/举证/立论的内容型条目 | ~652 |
| 备用 | 素材描写类（07x）、人生修养、幽默 | ~231 |

规则写在 `apply_use.py` 的 `tier_of()`。想调档只改那一处，重跑即可。

## 主题包（window.TOPICS）

11 个预设主题 = 一组关键词，在取用台里对 `word/syn/mean/example/scene` 做匹配。
**不打标签、零维护成本**，加一个主题只要在 `apply_use.py` 的 `TOPICS` 里加一条 `{name, icon, keys}`。

## 改数据的工作流

```bash
# 1. 改映射/规则 → 干跑看统计
python build/apply_use.py --src data.js
python build/apply_use.py --src data.js --apply     # 落盘（自动备份）

# 2. 批量补字段（{id: {字段: 值}} 的补丁）
python build/apply_patch.py --patch build/wordpatch/xxx.json --apply

# 3. 自测
node build/smoke.js    # 23 项结构断言，要求 23/23、0 运行时错误
node build/shot.js     # 真机截图到 build/shots/（需 playwright-core + 本机 Edge）
```

铁律：
- **只增条目，绝不重编 id**（打卡进度按 id 存云端，重编会串位）。
- `data.js` 固定 4 行 CRLF、JSON 无空格，改完用二进制校验 `\r\n` 结构与裸 LF = 0。
- `apply_*.py` 一律默认干跑，`--apply` 才落盘，落盘前自动备份到 `build/backup/`。
- **不要跑 `sync.py`**：md 源文件是旧版，跑一遍会把以上成果全部回退。
